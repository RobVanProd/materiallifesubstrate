## What was translated

The new isolated C++20 library and executable implement the accepted operation
graph, not a binary64 approximation to B96 and not a new numerical method.
Every packet phase component is a fixed 17-byte sign/precision/exponent/
96-bit-significand object (102 phase bytes per packet). Canonical packet
serialization is 118 bytes, plus the inherited stream header. This is not
a claim about aggregate runtime memory, C++ structure padding or performance.

Temporary Boost 1.83 integer/rational arithmetic computes the exact input to
each separately rounded B96 primitive. RN-even is applied at each registered
boundary, with the inherited exponent traps and canonical positive zero.
No rational value, residual or rounding history survives as packet phase
state. This is a software implementation of the accepted MPFR/B96 semantics;
it does not claim a formal proof of MPFR or of the C++ implementation.

Binary64 Path-B operations preserve explicit sequencing and existing FMA
sites; contraction elsewhere and fast-math are disabled. Binary64 input,
length, extension and conjugate bits are checked independently. Collective
energy, H_force, topology, reference, units and KDK are unchanged. The
exact aligned-integer chord predicate retains its scratch ledger and includes
the offending relation and literal failure certificate. Step state and
scientific events commit atomically; unsafe chords are not clipped/substepped.

The library is excluded from `mls_core` and built only with the explicit
`MLS_BUILD_KERNEL_PARITY_LAB` option. It is not included in the umbrella World
API, does not change World state and exposes an isolated research protocol.
Public World-facing API design is not settled by this lab.

## Controls and preserved corrections

The primitive corpus has a frozen seed of 260907 and 1,115 rational conversion
cases, including signs, ties/carries and exponent boundaries. There are 107
exact chord tests, canonical-wire rejection tests, initial coincidence and
atomic crossing checks, plus independently checked scientific-record and
model-input mutations. Seven separately compiled source mutants must be
rejected: toward-zero rounding, wrong precision, endpoint sign, omitted kick,
ignored chord, partial commit and altered force bits.

The first primitive attempt rejected a just-below-minimum value before RN96;
the accepted reference rounds that value to the minimum representable number.
This real translation defect was caught before any trajectory acceptance.
The failed executable, source and raw records are preserved. The correction
checks the rounded exponent, and the entire primitive corpus passes afterward.

Before first trajectory testing, serialization magic lengths were checked
against the frozen bytes and corrected. Later review added complete exact
domain-failure details, matched the order of relative subtraction and domain
validation, bounded the CLI process on Linux and Windows, and made output
line endings explicitly binary. Final replay rechecks the earlier accepted
scientific streams. Literal intermediate-state comparisons supplement the
already matching stage hashes. These are implementation/coverage corrections,
not changes to reference arithmetic or tolerances.

A synthetic range-rejection test subsequently found a failure-category
mismatch: both implementations preserved the prior state, but C++ exposed
`phase_range_failure:underflow` where Python returns `phase_range_failure`.
That exact failed source/executable/record is preserved. The final implementation
matches the category and propagates unrelated exceptions as errors rather than
misclassifying them as ordinary domain rejections. No accepted trajectory
changed; the additional fixture is a rejection test, not a new dynamics case.

The Linux address-space and Windows process-memory backstops are 2 GiB.
These are platform-specific resource backstops, not equal RSS measurements or
a performance claim. No reported passing trajectory hit its limit.

The inherited Lean project and trust boundary are required to remain green;
no new theorem claims to prove the executable or arbitrary-input equivalence.
The CI receipt requires GCC, Clang, MSVC, Python exact oracle and pinned Lean
