## What World now does in the quarantined target

The accepted kernel source, header and standalone app are unchanged. The new
World adapter calls that kernel in-process for each complete scheduled step.
It does not reinterpret B96 primitives, Path-B, forces, domain checks, KDK or
scientific event construction. The text/wire adapter is deliberately a semantic
integration boundary, not a performance optimization or production API choice.

World owns the complete canonical mechanics wire and frozen model/schedule
metadata. No expected next state, force value or comparison event enters the
causal path. No conversion into legacy integer packet coordinates occurs.
The mechanics packet-ID namespace is explicitly separate from legacy packet
handles; no implicit cross-representation identity map is invented.

World::step selects this path only with the research runtime enable. It stages
kernel state, scientific output and clock updates in a value-owned World copy,
validates the single-step result, and commits together. It does not also run
legacy ballistic drift. Failed steps preserve the previous World state, clocks
and committed observer output. Multi-step calls retain World's all-or-nothing
transaction semantics; the registered parity runs schedule one step per call.

The explicit build option `MLS_BUILD_WORLD_MECHANICS_LAB` is OFF by default.
It creates a separately named research World library and executable. Ordinary
`mls_core` and `mls_headless` are not activated; actual external compilation
checks show that research methods are absent from the default World API.
Runtime enable is also mandatory. Enabled-but-unattached stepping rejects.

mechanics. Its default format and physics ABI are unchanged.

The legacy checkpoint retains its existing policy of omitting debug packet
history and rebuilding the disposable grid on restore. No claim of preserving

legacy packet snapshots, grid contents, histories, materials and ledger state

Legacy totals/audit refuse to present an attached B96 system as exact integer

Physical-state hashing includes the attached mechanics configuration/state.
Observer snapshots are value copies; changing those copies or read frequency
does not change continuation. Exact checkpoint replay is not relabeled as
